# ADR-0001: 在庫整合性は楽観（Amazon 方式）で守る

- Status: Accepted
- Date: 2026-06-28

## Context

カートの在庫チェック（PR #3）に lock/queue が要るのでは？という問いから、在庫整合性をどこで守るかを再検討した。

リソースの整合性をどこまで厳密に守るかは技術ではなくビジネス判断であり、軸は「母数（大数の法則が効くか）」と「失敗コストを定額化・補償で吸収できるか」。母数が大きく損失総量が読めるなら楽観的に緩めてよく（Amazon の確定者勝ち・航空券のオーバーブック）、母数が小さく 1 件が致命的なら悲観的に厳密に守る（瞬殺商材の在庫引き当て）。

本サイトの商材は限定品だが、秒殺の争奪戦ではない。売り越しは補償（謝罪・キャンセル）で吸収できる規模と判断した。

## Decision

- **カートは在庫に無関心**。カートに入れても在庫を消費しない。カート段階のレースは構造的に無害（誰の在庫も減らない）
- **在庫の引き当ては注文確定時の 1 箇所だけ**。カートに入れた順ではなく、取引を成立させた順の早い者勝ち
- **排他は確定時の引き当てにだけかける**。`stock_movements` は追記テーブルのため、product_id 単位のアドバイザリロック（`pg_advisory_xact_lock`）で引き当てを直列化するのが第一候補
- **カート放置は許容（TTL 不要）**。確保しないので放置が在庫を奪わない
- **在庫の「表示」と「確保」は別物**。「残りわずか・売り切れ」の参考表示は可（約束はしない）

## Consequences

- カートにロック・キューは不要になり、在庫の防衛線は確定時の引き当て（UC-6）に一本化される
- 仮押さえ（予約 + TTL）モデルは採らない。予約期限管理・放棄カートの在庫解放・在庫の中間状態の二重管理というコストが現フェーズでは見合わない（YAGNI）
- **再検討の条件**: 秒殺の争奪戦になる商材（人気スニーカー抽選級）や発行枠つきクーポンなど、母数が小さく 1 件が致命的なリソースを追加するときは、そのリソース単位で悲観（仮押さえ・抽選）を別 ADR として検討する
