# ユースケース記述

`requirements.md` のユーザーストーリーを「誰が・何を・どうするか」という**振る舞い**として具体化したもの。
ドメイン言語（ユビキタス言語）で書き、実装詳細（テーブル名・カラム・SQL・HTTP ステータス）は持ち込まない。
データ構造は `erd.md`、API は `openapi.yaml` を参照。

## 用語（ユビキタス言語）

| 用語 | 意味 |
|---|---|
| 会員 | サイトを利用する顧客 |
| 商品 | 販売される品物。名前・価格・在庫を持つ |
| 在庫変動 | 入荷・出庫など在庫が増減した記録。**在庫はこの積み重ねで決まる** |
| カート | 会員が購入予定の商品を入れておく入れ物 |
| 注文・注文明細 | 確定した購入。明細は注文時点の単価を保持する |
| 決済 | 注文に対する支払い（本システムでは外部と繋がずモック） |

---

## UC-1 商品を登録する（管理者）

| 項目 | 内容 |
|---|---|
| アクター | 管理者 |
| 事前条件 | 認証済み |
| 事後条件 | 商品が登録され、初期在庫が在庫変動として記録される |

**基本フロー**

1. 管理者が商品（名前・価格・初期在庫・説明）を入力する
2. システムが入力を検証する（価格の上限など）
3. 商品を登録する
4. 初期在庫を在庫変動として記録する
5. 登録した商品を返す

**例外フロー**

- 2 で検証エラー → エラー一覧を返す（全エラーを収集）
- 3/4 で登録に失敗 → エラーを返す

## UC-2 商品一覧を見る（顧客）

| 項目 | 内容 |
|---|---|
| アクター | 顧客 |
| 事前条件 | なし（一覧は誰でも見られる） |
| 事後条件 | 在庫を含む商品一覧が得られる |

**基本フロー**

1. 顧客が商品一覧を要求する
2. システムが各商品と在庫を取得する
3. 一覧を返す

---

## UC-3 商品をカートに追加する（顧客）

| 項目 | 内容 |
|---|---|
| アクター | 顧客 |
| 事前条件 | 認証済み |
| 事後条件 | カートに商品が追加される |

**基本フロー**

1. 顧客が商品と数量を指定する
2. システムが在庫を確認する
3. 在庫が足りればカートに追加する

**例外フロー**

- 在庫がない → エラー
- 数量が在庫を超える → エラー
- 同じ商品が既にカートにある → エラー
- 商品が存在しない → エラー

---

## UC-4 カートの数量を変更する（顧客）

| 項目 | 内容 |
|---|---|
| アクター | 顧客 |
| 事前条件 | 認証済み・対象のカートの商品が存在する |
| 事後条件 | カートの商品の数量が変更される |

**基本フロー**

1. 顧客がカートの商品と新しい数量を指定する
2. システムが在庫を確認する
3. 在庫が足りれば数量を変更する

**例外フロー**

- カートの商品が存在しない → エラー
- 数量が在庫を超える → エラー

## UC-5 カートから商品を削除する（顧客）

| 項目 | 内容 |
|---|---|
| アクター | 顧客 |
| 事前条件 | 認証済み |
| 事後条件 | カートから商品が取り除かれる |

**基本フロー**

1. 顧客がカートの商品を指定する

**例外フロー**

---

## UC-6 注文を確定する（顧客）

| 項目 | 内容 |
|---|---|
| アクター | 顧客 |
| 事前条件 | 認証済み・カートに 1 件以上の商品がある |
| 事後条件 | 注文が作成され、在庫が減り、決済（モック）が行われ、カートが空になる |

**基本フロー**

1. 顧客が注文確定を要求する
2. システムがカートの内容を取得する
3. 各商品の在庫が注文数を満たすか確認する
4. 注文と注文明細を作成する（単価は注文時点の価格で確定する）
5. 出庫を在庫変動として記録する（在庫が減る）
6. 決済（モック）を行う
7. カートを空にする
8. 注文を返す

**例外フロー**

- カートが空 → エラー
- いずれかの商品で在庫が足りない → エラー
- 4〜7 のいずれかで失敗 → エラー（複数集約をまたぐため、本来は補償アクションを検討する → `.claude/rules/workflow.md`）
</content>
