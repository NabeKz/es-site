# ユースケース記述

- `requirements.md` のユーザーストーリーを「誰が・何を・どうするか」という**振る舞い**として具体化したもの
- 書き方の方針は `.claude/rules/usecase.md` を参照

## 用語（ユビキタス言語）

| 用語 | 意味 |
|---|---|
| 会員 | サイトを利用する顧客 |
| 商品 | 販売される品物。名前・価格・在庫を持つ |
| 在庫変動 | 入荷・出庫など在庫が増減した記録 |
| カート | 会員が購入予定の商品を入れておく入れ物 |
| 在庫引き当て | 注文のために在庫を確保すること |
| 注文・注文明細 | 会員の購入。明細は注文時点の単価を保持する |
| 注文の状態 | 受付（受け付けた）／確定（在庫引き当てと決済が完了した）／取消（在庫不足・決済失敗で取り消した） |
| 決済 | 注文に対する支払い（本システムでは外部と繋がずモック） |

## UC-1 商品を登録する（管理者）

| 項目 | 内容 |
|---|---|
| アクター | 管理者 |
| 事前条件 | 認証済み |
| 事後条件 | 商品が登録され、初期在庫が在庫変動として記録される |

**基本フロー**

1. 管理者が商品（名前・価格・初期在庫・説明）を入力する
2. システムが入力を検証する（価格の上限など）
3. 商品を登録する
4. 初期在庫を在庫変動として記録する
5. 登録した商品を返す

**例外フロー**

- 入力に不備があれば登録できず、不備はすべてまとめて知らせる
- 登録に失敗したときは、商品も初期在庫も記録されない

## UC-2 商品一覧を見る（顧客）

| 項目 | 内容 |
|---|---|
| アクター | 顧客 |
| 事前条件 | なし（一覧は誰でも見られる） |
| 事後条件 | 在庫を含む商品一覧が得られる |

**基本フロー**

1. 顧客が商品一覧を要求する
2. システムが各商品と在庫を取得する
3. 一覧を返す

---

## UC-3 商品をカートに追加する（顧客）

| 項目 | 内容 |
|---|---|
| アクター | 顧客 |
| 事前条件 | 認証済み |
| 事後条件 | カートに商品が追加される |

**基本フロー**

1. 顧客が商品と数量を指定する
2. システムが在庫を確認する
3. 在庫が足りればカートに追加する

**例外フロー**

- 存在しない商品はカートに追加できない
- 在庫がない商品はカートに追加できない
- 在庫数を超える数量はカートに追加できない
- すでにカートにある商品は重ねて追加できない

---

## UC-4 カートの数量を変更する（顧客）

| 項目 | 内容 |
|---|---|
| アクター | 顧客 |
| 事前条件 | 認証済み・対象のカートの商品が存在する |
| 事後条件 | カートの商品の数量が変更される |

**基本フロー**

1. 顧客がカートの商品と新しい数量を指定する
2. システムが在庫を確認する
3. 在庫が足りれば数量を変更する

**例外フロー**

- 存在しないカートの商品は数量を変更できない
- 在庫数を超える数量には変更できない

---

## UC-5 カートから商品を削除する（顧客）

| 項目 | 内容 |
|---|---|
| アクター | 顧客 |
| 事前条件 | 認証済み |
| 事後条件 | カートから商品が取り除かれる |

**基本フロー**

1. 顧客がカートの商品を指定する
2. システムがカートから商品を取り除く

**例外フロー**

- 存在しないカートの商品は削除できない

---

## UC-6 注文を確定する（顧客）

| 項目 | 内容 |
|---|---|
| アクター | 顧客 |
| 事前条件 | 認証済み・カートに 1 件以上の商品がある |
| 事後条件 | 注文が受け付けられ、注文処理（ワークフロー）が起動される |

受け付けた後の在庫引き当て・決済・確定と、失敗時の補償は、注文処理ワークフローが非同期で行う。

**基本フロー**

1. 顧客が注文確定を要求する
2. カートの内容で注文を受け付ける（注文を「受付」にする）
3. 注文処理（ワークフロー）を起動する
4. 「注文を受け付けた」ことを顧客に返す

**例外フロー**

- カートが空のときは注文を受け付けない
